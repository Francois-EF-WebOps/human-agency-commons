# Roadmap

This roadmap prioritises trustworthy foundations over breadth. Technology and implementation work should follow verified needs; the existence of a technical possibility is not evidence of a local need.

## Phase 0 — Repository integrity

- [x] Establish the public repository and project scope.
- [x] Publish initial contribution, conduct, and governance guidance.
- [x] Define evidence and harm-review expectations.
- [ ] Review repository rendering on GitHub mobile.
- [ ] Choose and document a project-wide licence after checking intended reuse and contribution terms.

## Phase 1 — Evidence baseline

- [x] Add an initial source register with official, institutional and local-language sources.
- [x] Create an initial claim ledger that separates evidence, inference, uncertainty, and what a source does not establish.
- [x] Record first-pass evidence and limitations for labour, essential consumption, water access, connectivity, food/climate and CPI.
- [x] Record unresolved topics and next verification steps rather than filling gaps with assumptions.
- [ ] Verify primary INE tables for water and labour indicators.
- [ ] Inspect ADECO's original ICE calculation reports.
- [ ] Review full World Bank economic and climate reports.
- [ ] Add dedicated sources for healthcare, housing, education-to-work, unpaid care, waste/energy and media/influence.
- [ ] Include further local-language reporting and perspectives from additional islands.
- [ ] Research digital access, device/data affordability, digital public services, accessibility, local repair/skills capacity, and platform/AI impacts using traceable sources before making Cabo Verde-specific claims.

## Phase 2 — Response and technology design

- [x] Add a technology, application and implementation framework that treats technology as an option, not the default.
- [x] Add a reusable implementation plan template covering outcomes, alternatives, cost, operations, safeguards and evaluation.
- [ ] Validate problem framing with people who understand the relevant island, municipality, and community context.
- [ ] Map existing services, community initiatives, and proven interventions before proposing new ones.
- [ ] Compare practical cost, access, staffing, infrastructure, and maintenance requirements.
- [ ] Identify exclusion risks, privacy risks, consent requirements, and exit options.
- [ ] For any proposed technical solution, compare non-digital, existing-tool, and build-new options; record why the chosen approach is proportionate.
- [ ] Define requirements and acceptance criteria before development or procurement.
- [ ] Confirm an accountable operator, support route, maintenance capacity, funding continuity, and non-digital fallback before any live pilot.

## Phase 3 — Small tests and evaluation

- [ ] Select one low-cost, reversible test with local collaborators.
- [ ] Agree on baseline, intended outcome, duration, and stop criteria before starting.
- [ ] Test usability, accessibility, privacy, security, failure recovery and low-connectivity conditions where relevant.
- [ ] Record adverse effects and unintended outcomes, not only successes.
- [ ] Publish results with limitations and enough method detail to interpret them safely.
- [ ] Distinguish a working prototype from an operated service and from an intervention with evaluated outcomes.

## Phase 4 — Operation, adaptation and reuse

- [ ] Assign ongoing ownership, maintenance, support, incident response and update responsibilities.
- [ ] Monitor total cost, dependency risks, accessibility and real-world outcomes.
- [ ] Define data export, migration, fallback and retirement procedures.
- [ ] Make reusable templates and plain-language summaries.
- [ ] Invite translation and adaptation for other communities.
- [ ] Preserve local context; do not assume a successful intervention transfers unchanged.

## Definition of progress

Progress means better evidence, clearer choices, safer and more accessible participation, and demonstrable improvement in outcomes—not simply more files, activity, claims, apps, or features. A solution is not implementation-ready without accountable operation, maintenance, safeguards, and a credible way to assess whether it helped.
